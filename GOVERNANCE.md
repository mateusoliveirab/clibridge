# Governance

Clibridge is currently maintainer-led. The maintainer decides on releases,
security response, roadmap, and merge approval, while public discussion and
evidence are preferred for ordinary changes.

## Decisions that need discussion first

Open an issue or discussion before a pull request when changing the public MCP
contract, adding/removing a provider, changing execution or approval policy,
altering persisted ledger data, or introducing a dependency with a material
security or licensing impact.

Small fixes, tests, documentation improvements, and isolated internal refactors
may be proposed directly when they follow the contribution and testing guides.

## Maintainer expectations

Maintainers review evidence in proportion to risk, protect private security
reports, avoid merging unreviewed provider-execution changes, and keep release
notes accurate. This document describes the current lightweight model and may
evolve as the contributor community grows.
